## BY HAND: what the source does not give mechanically
#
# This section is tools/surface_by_hand.txt, copied in whole. Each item is
# a part of the surface that tools/surface.shale cannot read from the code,
# so it is said here, with where the code holds it. An item moves out of
# this list once the tool learns to read it.

### Argument forms the arity column does not show
  edit(p, old, new[, {all, word}]) and edit(p, {{old, new[, all][, word]}, ...}), at most 64 edits a call; the option column lists both forms' keys (builtins_change.zig)
  sort(l[, "asc" | "desc"]), sort(rows, key[, order]), sort(rows, {k1, ...}[, order]), each key a name or {key = name, desc = true}, at most 8 keys (builtins_lists.zig)
  read(p[, offset[, n]]), read_lines(p[, offset[, n]]), count_lines(p[, offset[, n]]), count_in(p, s[, offset[, n]]), find_in(p, s[, offset[, n]]): offsets 0-based
  re_find's `from` is re_find's alone: re_match, re_replace and re_find_all share its option reader, which passes `from` only for re_find (builtins_regex.zig optionsArg), so the option column overstates them
  min(a, b[, c[, d]]), max: two to four integers; path(a[, b[, c[, d]]]): one to four parts
  print(...) takes any number of scalars; tostring and print write nil, true, false, the integer, the string (builtins.zig scalarText)
  host(name, ...) is the core's one door; the Linux host's names are listed above, and metal's host has none (class `host`, "`{s}`: not on this host")
  attempt(f, ...) is the language's, never a builtin: f is a script function declared above; it gives {ok, value} or {ok = false, error, class, line, column, in_function, trail}
  use("mount:path.shale") is a top-level statement with one string literal (parse.zig)
  glob(pattern[, {hidden}]) checks its own key by hand, not through opts_only, so its options show as "-"; the same for any prelude function that reads opts without opts_only or git_opts

### What a value prints as, and what a builtin gives back
  The shapes builtins return (stat's {size, kind, modified}, walk's {path, size, kind, modified} and its {kind = "more"} entry, re_find's {at, text[, groups, group]}, read_lines' {lines, next, done}, run's {argv, code, ended, ms, cpu_ms, out, ...}, job_wait's {ended[, code | signal]}, procs' {pid, ppid, uid, name, args, start}, the tree readers' nodes) are in docs/SHALE.md and docs/SHALE-AGENTS.md, not read here
  table(rows, columns): two spaces between columns, a column of integers aligned right, no newline at the end (builtins_format.zig)
  human(bytes): one decimal, rounded half up, B to EiB; date(seconds): 2026-10-14T03:00:00Z (builtins_format.zig, builtins_time.zig)
  The order of a map's keys is the order first set, and every walk of a map keeps it

### The store's own texts
  A `store` stop's text ends with the store's error, named by zig-webbox's `store` (`FileNotFound`, ...): those names are zig-webbox's, outside this repo, and differ between Linux and metal (builtins_store.zig errorName)
  The store's limits on a name, a path's length and its depth are zig-webbox's (`is_name`'s rule: 1 to 96 bytes of printable ASCII, none of "*/:<>?\|, not . or .., not ending in . or a space)

### Steps and costs
  Every builtin's charge (a step a byte or item, a step for 16 bytes of bulk work, a sort's bound before it runs, a search's stops and compares) is the count `budget()` and `── used:` show, so it is observable; it is held by src/script/charge_test.zig, not by a table here
  EXCEPTION: the arena's byte counts (`budget().arena_bytes`'s value, the exact step where `budget arena` stops) are outside the frozen surface (Steve, 2026-11-17); an arena stop's class and message are inside it: docs/C-SEAMS.md, "Fidelity"

### The CLI
  Exit codes: 0 the script finished, 1 it stopped (a check's stop too), 2 the run could not begin: the command line, the script's file, stdin, the mounts, a prelude, a `-- budget:` line, SHALE_NOW (script_runner.zig main's `return 2`s)
  stdout carries the script's output and an edit's summary line; stderr carries the header's budgets line, the report, `── time:`, the jobs' lines and the undo's lines, in that order (script_runner.zig main)
  A refusal of the command line prints "shale: <why>" and then the usage
  The script's name in a stop: its FILE as given, "-e", or "stdin" (cli.zig scriptName); a line in a prelude is that prelude's name, a library's its path, the core prelude's "the prelude" (cli.zig placeOf)
  `--help` prints the usage, the docs' paths and the mounts (a secrets mount's folder never shown); `--version` prints "shale <mode>" (script_runner.zig help)
  `NAME=VALUE`s a script never reads with `arg` stop the run before it starts (parse.zig unreadArgStop), unless a name is made as the script runs
  The header's `-- budget:` line: among the opening comments, at most one, the command line's `--budget` winning (cli.zig headerBudgets)
  `--undo-on-stop` keeps at most 64 MiB of prior state (shale_host_linux.zig)
  `call_depth` is settable by `--budget` though the usage text does not list it (cli.zig settable against usage): a drift to settle, not to port silently

### The mounts file
  One `name = value` a line; `#` comments and blank lines passed by; the value an absolute path or `~/...`; then any of ro, tools, secrets, each once, secrets and tools not both, secrets implying read-only (shale_host_setup.zig parseMounts)
  A mount's own path is resolved once, at load; below it no symbolic link is followed (shale_host_linux.zig refuseLinks)
  A missing default file is no mounts; a missing SHALE_MOUNTS file is an error naming it

### The gate
  It passes `[cd DIR && ]shale` or an absolute path ending /shale, then --verbose, --undo-on-stop, --args-stdin, --help, --version, --budget NAME=N and plain words, optionally a `<<'TAG'` heredoc (TAG [A-Z_]+) whose last line is TAG and no earlier line is
  Or the escape: a first line `# want: <tag>: <text>` or `# out-of-scope: <tag>: <text>`, tag [a-z0-9-]+, logged to ~/.local/state/shale/wants.tsv as date, session, kind, tag, text and the command's first 160 bytes, tabs and newlines escaped (tools/shale_gate.zig)

### The browser and the route
  The wasm build's exports (src/shale_wasm.zig) and the signed route's envelope (src/script_route.zig's header) are surfaces of their own, listed here only by name: the route's refusal texts are above, its statuses (400, 403, 409, 500, 501, 503) are in docs/SHALE.md
